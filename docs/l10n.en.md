# Talkies in your language

*This document in: [English](l10n.en.md) · [Español](l10n.md)*

Talkies' screens used to be written in English **inside the code**: `res/values/strings.xml` had four entries while
the Java had ~190 places that put a word on the screen. Translating was therefore not a matter of adding a `values-es`
folder but of moving each screen's text into resources first, one whole screen at a time. That is finished: **every
word the TV shows now comes out of resources**, in both languages, and Spanish is what comes up when it boots.

## How it works today

- **Talkies settings → Language** cycles **Auto → English → Español**. Auto follows the TV, which is right most of
  the time — but plenty of TVs stay on "English (United States)" wherever they are sold. That row is
  [Lang.java](../app/src/main/java/com/techpp/glass/Lang.java): it stores `lang` in the `home` preferences and
  `HomeActivity.attachBaseContext` wraps the context with that locale, so the resources resolve in it. With nothing
  stored yet the default is **es**, which is what this copy boots into. Changing it restarts Home (`recreate()`),
  because every label is read from the resources.
- **`Lang.wrap` sets `Locale.getDefault()` too** (DISPLAY and FORMAT): `createConfigurationContext` leaves those
  alone, and they are what `DateFormat` and `SimpleDateFormat` read. Without them the labels would say "lunes" while
  the date went on saying "Monday". The screensaver does the same in its `attachBaseContext`.
- **What the language does not change**: the country the picks, scores and °C/°F come from is `Region`'s business,
  which reads the TV's time zone. Español moves no data and no settings.
- **Two surfaces are translated on the way to the screen**, because their text is read back for something else:
  `Weather.shown()` (the saved line keeps saying `27° Sunny`, which is where the icon picks its drawing and the rain
  note its "not already raining") and `Devices.label()` (the names Talkies makes up: Sistema de sonido,
  Descodificador…).
- TMDB's genre names are already asked for in the language on screen (`/genre/list?language=es`), and the week-old
  `setup` cache keeps the language in its key, so choosing another one fetches them again.

## Adding a string

1. `res/values/strings.xml`: the English text, named for what it is (`remove_from_dock`, not `row_3`).
2. `res/values-es/strings.xml`: the same name, Spanish text. Apostrophes escape as `\'`.
3. At the call site, `getString(R.string.remove_from_dock)`. In a row: `addRow(getString(...), detail, action, false)`.
4. Build: `./gradlew assembleDebug`. Nothing else — the locale is picked at runtime.

Two rules keep it sane: **move a whole surface per phase**, so no menu is half in each language; and **keep names
Android or the TV shows** (`Turn off`, an app's own label) in the language the device uses. The two lists (493 names
each) are compared with a `grep` of `name=`: different counts mean a translation is missing.

## What stays English, and why

- **The code, its names and its comments.** What is translated is what is seen, not what is read in an editor.
- **Whatever Android or the TV writes**: its own dialogs, each app's name.
- **What the services answer**: ESPN's leagues and incidents (`Premier League`, `Day 1: Stumps`), TMDB's titles and
  overviews. That would mean translating somebody else's data with a dictionary of our own.
- **The phone's page** ([PhonePage.java](../app/src/main/java/com/techpp/glass/PhonePage.java)): HTML that opens on
  the phone, not on the TV. It is the one surface left, if it ever matters.

## Checking a translation

There is no emulator in this project and the text is on a TV, so a phase is checked by reading it on screen:
install, set Language → Español, and walk the surface that moved. `./gradlew assembleRelease` matters as much as the
debug build, since shrinking can drop a resource nothing in Java names.
