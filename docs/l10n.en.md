# Talkies in your language

*This document in: [English](l10n.en.md) · [Español](l10n.md)*

Talkies' screens are written in English **inside the code**, not in resources: `res/values/strings.xml` had four
entries while the Java has ~190 places that put a word on the screen (132 settings and menu rows, 36 toasts, 19
`setText`, a few titles). So translating is not adding a `values-es` folder — it is moving each screen's text into
resources first, one screen at a time. This folder does that in phases, and each phase leaves a whole surface in
both languages rather than half a menu in each.

## How it works today

- **Talkies settings → Language** cycles **Auto → English → Español**. Auto follows the TV, which is right most of
  the time — but plenty of TVs stay on "English (United States)" wherever they are sold, and a Spanish screen then has
  no way to ask. That row is [Lang.java](../app/src/main/java/com/techpp/glass/Lang.java): it stores `lang` in the
  `home` preferences and `HomeActivity.attachBaseContext` wraps the context with that locale, so the resources resolve
  in it. Changing it restarts Home (`recreate()`), because every label is read from the resources.
- **It changes labels only.** The country the picks, scores and °C/°F come from is `Region`, which reads the TV's time
  zone and the system locale — `createConfigurationContext` leaves `Locale.getDefault()` alone, so Español moves no
  data and no URLs.
- **Phase 1 is done**: the menu that hold-OK opens on an app (Add to dock / Remove from dock / Move / Change image /
  Remove from Home / Hide / Uninstall / App info), the **All apps** button, and the Language row itself. Also
  `sleep_service_description`, which is Android's own scary accessibility warning and the first thing a Spanish reader
  meets, and `watch_service_label`.

## Adding a string

1. `res/values/strings.xml`: the English text, named for what it is (`remove_from_dock`, not `row_3`).
2. `res/values-es/strings.xml`: the same name, Spanish text. Apostrophes escape as `\'`.
3. At the call site, `getString(R.string.remove_from_dock)`. In a row: `addRow(getString(...), detail, action, false)`.
4. Build: `./gradlew assembleDebug`. Nothing else — the locale is picked at runtime.

Two rules keep it sane: **move a whole surface per phase**, so no menu is half in each language; and **keep names
Android or the TV shows** (`Turn off`, an app's own label) in the language the device uses.

## Phases left, with what each one touches

| Phase | Surface | Roughly |
|---|---|---|
| 2 | The rest of **Talkies settings**: the five group headings and its ~40 rows, plus the "Finish setup" checklist | 45 sites |
| 3 | **Control Center** and its submenu rows (weather hours and days, sleep timer, Bluetooth, sound, speed test) | ~30 |
| 4 | **Toasts and errors** — the sentences that explain what just happened, the ones people actually read | 36 |
| 5 | Home's own furniture: clock and date format, greeting, weather line, row titles (Trending, New in…, Continue watching), and `RecentsCards.ACTIONS` | ~25, plus date formats |
| 6 | The other four files that write text (`RemoteKeys`, `ScoreCard`, `SelfUpdate`, `SleepService`) and the **screensaver** ([Screensaver.java](../app/src/main/java/com/techpp/glass/Screensaver.java)), which is its own component and needs `Lang.wrap` in its own `onCreate` | ~25 |

Phase 5 is the delicate one: dates and "New in India" need the *inflected* forms, so they use the framework's own
formatting (`DateFormat`, `Region.name`) rather than string concatenation. Anything with a number inside
("`3 steps left`") wants `<plurals>`, not a literal stitched together at the call site — see `setupMissing()` at
[HomeActivity.java:3989](../app/src/main/java/com/techpp/glass/HomeActivity.java#L3989).

## Checking a translation

There is no emulator in this project and the text is on a TV, so a phase is checked by reading it on screen:
install, set Language → Español, and walk the surface that moved. `./gradlew assembleRelease` matters as much as the
debug build, since shrinking can drop a resource nothing in Java names.
